# Насадка-имя на карандаш

Объёмное имя, которое надевается на карандаш или ручку: буквы слиты в одно тело,
вдоль него проходит сквозной канал под грань карандаша.

За основу взята модель MakerWorld
[#2374615 «Nome infilabile matita parametrico»](https://makerworld.com/ru/models/2374615-customizable-parametric-pencil-slide-on-name).
Её онлайн-конструктор заменён собственным генератором: имена считаются локально,
пакетом, без веб-интерфейса и без расхода кредитов.

## Структура

| Папка | Что внутри |
|---|---|
| `Заготовки/` | **примеры**: STL и 3MF, скачанные из конструктора MakerWorld. Эталон для сверки, на печать не идут |
| `Готовые модели/` | **на печать**: STL, 3MF под A1 и `.scad` рядом; в `Плиты/` — готовые столы на всю группу |
| `Скрипты/` | генератор, шаблон OpenSCAD, сборщик 3MF, раскладка на стол, рендер превью |
| `fonts/` | шрифт Shantell Sans ExtraBold (SIL OFL 1.1, есть кириллица) |

## Быстрый старт

Нужны OpenSCAD и Python с `fontTools` (для превью — ещё `matplotlib`).

```bash
python "Скрипты/generate_names.py" ДИМА ИЛЬЯ ЯСМИНА --hole 7.8
```

Список имён можно держать в файле:

```bash
python "Скрипты/generate_names.py" --file "Скрипты/names.txt" --hole 7.8
```

Список группы из садика (CSV «Фамилия, имя, отчество;Дата рождения») —
берётся второй токен ФИО, приводится к верхнему регистру:

```bash
python "Скрипты/names_from_csv.py" "дети.csv" --skip ИЛЬЯ ЯСМИНА --out "Скрипты/names.txt"
```

Одинаковые имена схлопываются в один STL, но скрипт считает, сколько детей
носит каждое имя, — печатать нужно по числу детей, а не по числу файлов.

Проект Bambu Studio под A1 из готового STL:

```bash
python "Скрипты/make_3mf.py" "Готовые модели/МАКСИМ_7.8.stl"
```

Картинка для проверки перед печатью:

```bash
python "Скрипты/preview.py" "Готовые модели/ДИМА_7.8.stl" -o превью.png
```

|---|---|---|---|

| `dimensione testo` | `--size` | `12` | размер шрифта |

| — | `--spacing` | `0.84` | множитель шага между буквами |
| — | `--min-spacing` | `0.5` | ниже этого шаг стыка не опускается |
| — | `--weld` | `1.2` | мин. толщина перешейка на стыке букв, мм |

## Как устроена геометрия

Разобрано обмером эталонного `Заготовки/ДИМА_7.8.stl`:

* все буквы стоят на общем дне `Z = 0` — печатается без поддержек;
* **«зигзаг» — это разная ВЫСОТА букв, а не сдвиг по вертикали:**
  чётные `10 + 0.9 = 10.9` мм, нечётные `10 − 0.25 = 9.75` мм
  (в эталоне ровно две плоскости верха: `10.900` и `9.750`);
* канал под карандаш идёт вдоль оси X; диаметр круга точно равен заявленному
  (`7.800` и `7.400` в двух версиях эталона), сверху к нему добавлен конёк;
* по вертикали центрируются **тела букв** (без диакритики), ось канала
  проходит по `Y = 0` — см. раздел про центрирование ниже.

Буквы одной высоты объединяются в 2D и выдавливаются одним `linear_extrude`.
Объединять N отдельных объёмных букв в 3D CGAL считает примерно вдвое дольше
при том же результате.

## Два неочевидных момента

**Шрифт.** OpenSCAD ищет шрифты только через fontconfig: `C:\Windows\Fonts`,
`%LOCALAPPDATA%\fonts` и `~/.fonts`. Папку проекта и `OPENSCADPATH` он для
шрифтов **не** смотрит, поэтому генератор сам кладёт копию `.ttf` в `~/.fonts`
— без прав администратора и без записи в реестр.

**Масштаб.** `text(size=N)` в OpenSCAD — это не размер em. Для Shantell Sans
одна единица `size` равна 720 font-units, а не 1000. Коэффициент зависит от
шрифта, поэтому генератор измеряет его один раз пробным рендером глифа и
кеширует в `Скрипты/.font_calibration.json`.

## Четыре способа испортить деталь

Деталь может выйти негодной четырьмя разными способами, и лечатся они
по-разному. После генерации считается число связных компонент меша,
толщина пола под каналом, свода над ним и стенки сбоку.

### 1. Расходящиеся стыки букв — свой множитель на каждый стык

В рукописном шрифте пары расходятся неодинаково. В имени `АНТОНИНА` почти все
стыки смыкаются при обычном `0.84`, а пара `ТО` — только при `0.62`: у `Т`
внизу тонкая ножка, у `О` слева круглый бок.

Ужимать ради одной пары всё слово нельзя — остальные буквы слипаются в кашу
(`АНТОНИНА` при глобальных `0.62` сжимается с 80 до 64 мм и теряет
читаемость). Поэтому множитель подбирается **отдельно для каждого стыка**,
остальные не трогаются вовсе:

```
МАРГАРИТА:  МА 0.84 · АР 0.84 · РГ 0.829← · ГА 0.723← ·
            АР 0.84 · РИ 0.813← · ИТ 0.84 · ТА 0.702←
```

**Критерий — не «слиплось», а «перешеек не тоньше `--weld`» (1.2 мм).**
Разница принципиальная: соприкоснуться буквы могут по касательной, и такой
стык отломится. Первая версия останавливалась на первом же контакте и давала
`ТО` толщиной **0.48 мм** — одна линия экструзии.

Толщина меряется эрозией объединения пары: `offset(r = -weld/2)` съедает по
контуру, и если пара осталась единым непустым телом, самое узкое место шире
`weld`. Поиск двоичный по множителю — тест монотонен (теснее буквы, толще
перешеек), хватает 6-8 прогонов на проблемный стык.

Диакритика из этого замера **исключается**: галочка над `Й` к соседней букве
не крепится, а её тонкие места ломают измерение — эрозия находит самое узкое
место где угодно, а нам нужен именно стык. Буква обрезается по верху тела.

Проверка идёт на паре букв и на черновом `$fn`: дёшево, а тессиляция там
срезает дуги внутрь, так что результат консервативен.

Что дала переделка:

| Стык | Было | Стало |
|---|---|---|
| `ТО` в АНТОНИНА | 0.48 мм | 1.29 мм |
| `ТА` в МАРГАРИТА | 0.57 мм | 1.18 мм |
| `АТ` в МАТВЕЙ | 0.79 мм | 1.35 мм |

Если нужной толщины не добиться никаким шагом, генератор откатывается к
критерию простого касания и говорит об этом вслух — молча слабый стык
не пропускается. На комплекте группы такого не случилось ни разу:
независимый замер по всем проблемным стыкам дал минимум **1.18 мм**.

### 2. Центрирование по вертикали: общая полоса, а не габарит

Канал под карандаш идёт по `Y = 0` и занимает `±3.9` мм. Чтобы у **каждой**
буквы под каналом и над ним остался одинаковый запас, канал ставится в
**общую полосу** всех букв: от самого высокого низа до самого низкого верха.
Всё, что торчит за полосу — хвост `Д`, бревис `Й`, — лишний материал,
он ничему не мешает.

Считать по общему габариту нельзя, и это два разных бага с противоположным
знаком.

**Хвост `Д` тянет центр вниз.** Он на 3.3 мм ниже базовой линии. По габариту
центр уезжает вниз на половину этого, и у всех *остальных* букв под каналом
остаётся одна линия экструзии. `ДИМА` и `АЛЕКСАНДР` ломались именно так,
а контроль стенки рапортовал 3.7 мм — он мерил до низа `Д`, не той буквы.

| Имя | Буквы без хвоста: было → стало |
|---|---|
| `ДИМА` | И/М/А **0.60–0.67 → 2.08–2.15** мм |
| `АЛЕКСАНДР` | все восемь **0.52–0.68 → 2.06–2.23** мм |
| `ФЁДОР` | 1.47–1.58 → 2.06–2.18 мм |

**Бревис `Й` тянет центр вверх.** Он торчит на 4.4 мм выше буквы. По габариту
центр уезжает вверх — и канал вылезает над буквами, вскрывая их сверху
жёлобом. Насколько всё плохо было:

| Имя | Стенка над каналом (было) | Стало |
|---|---|---|
| `АРСЕНИЙ` | **−0.02 мм** — канал прорезал буквы насквозь | 2.19 мм |
| `МАТВЕЙ` | **0.02 мм** | 2.23 мм |
| `ЕВГЕНИЙ` | **0.02 мм** | 2.23 мм |
| `ТИМОФЕЙ` | 1.82 мм | 3.11 мм |

Проверка по готовому STL: у старого `АРСЕНИЙ` материал выше канала был
только на 3.9 мм из 68.8 мм длины (сам бревис), остальные буквы стояли
разрезанными. После исправления — 66.8 мм из 68.8.

Теперь по вертикали центрируются тела букв, а диакритика просто торчит выше,
как ей и положено: габарит модели по `Y` стал несимметричным
(`−6.09 .. 10.51` у `АРСЕНИЙ`). Генератор печатает толщину этой стенки
в отчёте рядом со сводом и ругается, если она меньше 1 мм. На комплекте
группы минимум — 2.16 мм.

### 3. Провисание крыши канала — конёк на 45°

Верх канала печатался горизонтальным мостом, и его первые нити провисали
внутрь отверстия. Сопли цепляли карандаш и царапали его — приходилось перед
использованием сбивать их запасным карандашом.

Лечится формой канала: над кругом ставится **конёк** — крыша на 45°. Скаты
выходят из точек, где касательная к кругу идёт под 45°, и сходятся на высоте
`r · √2`. Горизонтального участка не остаётся вовсе, значит и мостить нечего.
Скаты под 45° печатаются сами, без поддержек.

По слайсеру на имени `МАРК`:

| | Мост | Навесные стенки |
|---|---|---|
| Без конька | 6.04 с | **14.68 с** |
| С полным коньком | 2.83 с | **0.13 с** |

Круг под карандаш при этом не трогается: замер по модели на высоте оси даёт
ровно `−3.900 .. +3.900`. Конёк только добавляет пустоту сверху.

**Цена — высота, и конёк подбирается по месту.** Полному коньку нужно
`r · (√2 − 1) ≈ 1.6` мм над кругом плюс материал сверху. Если столько нет,
ставится урезанный: скаты те же, но между ними остаётся площадка шириной
`2 · (полный − урезанный)`, которая всё-таки мостится. Генератор сам берёт
максимум, который влезает, оставляя над коньком не меньше 1 мм:

| Базовая высота | Общая | Конёк | Над коньком | Навесные стенки на `МАРК` |
|---|---|---|---|---|
| `10` | 10.9 мм | не влезает | 0.85 мм | 14.68 с |
| `10.5` | 11.4 мм | 0.35 мм | 1.00 мм | 9.90 с |
| `11` | 11.9 мм | 0.85 мм | 1.00 мм | 5.15 с |
| `12` | 12.9 мм | полный 1.62 | 1.23 мм | **0.13 с** |

Полностью провисание убирает только полный конёк, то есть высота `12`.
На меньшей высоте это компромисс: `10.5` срезает треть провисаний,
`11` — две трети.

Ось канала при этом **осталась на прежней высоте**: пол под каналом
печатается на столе и тонким быть может, поэтому весь прирост ушёл наверх,
где он и нужен. По умолчанию ось ставится так, чтобы под каналом остался
пол `1.1` мм (`--bore-z` задаёт вручную).

### 4. Висящие части глифов — посадка диакритики

Точки у `Ё` и бревис у `Й` — отдельные контуры глифа. После выдавливания они
становятся самостоятельными столбиками: к букве не крепятся вообще и на печати
просто остаются лежать на столе. Зазоры маленькие — `0.57–0.60` мм у `Ё`
и `0.85` мм у `Й`, — но этого достаточно, чтобы деталь развалилась.

**Основной способ — посадка, а не перемычки.** Глиф режется по середине
зазора, верхняя часть опускается вниз, пока её кончики не врастут в тело
буквы. Никаких посторонних прямоугольников: бревис `Й` садится между
верхушками штрихов `И`, точки `Ё` — на перекладину `Е`. Так `Й` и рисуют
в жирных шрифтах.

Глубина посадки подбирается тем же эрозионным тестом, что и стыки букв:
буква после `offset(r = -weld/2)` обязана остаться одним телом. У `Ё` точки
держат уже при спуске на `1.07` мм, у `Й` кончики бревиса и верхушки
штрихов скруглённые — им нужно уйти на `2.85` мм, чтобы было за что
зацепиться.

Путь сюда был извилистый, и обе развилки стоит помнить:

* **Одна перемычка по центру** — у `Ё` садилась на перекладину, а у `Й`
  вставала в просвет между штрихами `И`, над пустотой, и цепляла их только
  уголками. Проверка связности видела «одно тело», а эрозия на 0.1 мм уже
  рвала его — бревис отвалился при снятии со стола.
* **Две перемычки по штрихам** — держали (эрозия 0.6 мм), но читались как
  посторонние прямоугольники под галочкой. Остались в коде как
  `--bridge-style strokes`, есть и `center`; у перемычек можно задать
  высоту долей от буквы (`--bridge-height`).

Отключается ключом `--no-bridges`.

Затрагивает 5 имён группы: `ФЁДОР` (две перемычки) и `АРСЕНИЙ`, `ЕВГЕНИЙ`,
`МАТВЕЙ`, `ТИМОФЕЙ` (по одной).

Итог сверки с эталонами MakerWorld (габариты, мм):

| Имя | Генератор | Эталон |
|---|---|---|
| ДИМА | 49.21 × 15.23 × 10.90 | 49.30 × 15.08 × 10.90 |
| ИЛЬЯ | 38.35 × 12.27 × 10.90 | 37.28 × 12.18 × 10.90 |
| ЯСМИНА | 64.68 × 12.18 × 10.90 | 63.63 × 12.18 × 10.90 |
| МАКСИМ | 70.01 × 12.18 × 10.90 | — (в конструкторе не делалось) |

Расхождение до 1.5% — генератор не применяет кернинг (GPOS), который
использует конструктор MakerWorld. На посадку на карандаш это не влияет:
диаметр канала выдерживается точно.

## Раскладка на стол

Печатать 28 насадок по одной дорого не самим временем, а накладными расходами:
Bambu тратит ~6 минут подготовки плюс полторы минуты таймлапса на **каждый**
запуск, и это ещё 28 снятий детали со стола. `make_plate.py` собирает всё
в один проект, а количество копий берёт из списка группы — если детей с одним
именем двое, на стол кладутся две штуки.

```bash
python "Скрипты/make_plate.py" --csv "дети.csv" --rename ДМИТРИЙ=ДИМА
python "Скрипты/make_plate.py" --csv "дети.csv" --rename ДМИТРИЙ=ДИМА --per-plate 14
```

Упаковка полочная: детали сортируются по ширине и раскладываются рядами.
Насадки — длинные тонкие полоски, поэтому ряды выходят плотными и простой
алгоритм даёт результат близко к оптимальному. Рядом кладётся `раскладка.png`
со схемой стола.

Что получилось на группе (всё проверено прогоном через слайсер):

| Вариант | Время | Пластик | Циклов |
|---|---|---|---|
| 28 отдельных запусков | ~9.2 ч печати + ~3.6 ч накладных ≈ **12.8 ч** | 98 г | 28 |
| Одна плита на 28 шт. | **8 ч 04 мин** | 94.8 г | 1 |
| Две плиты по 14 шт. | **8 ч 13 мин** (4:21 + 3:51) | 94.8 г | 2 |

Разбивка на две плиты стоит всего 9 минут, зато вдвое уменьшает потери, если
что-то отвалится посреди печати. Оба варианта лежат в `Готовые модели/Плиты/`.

Перемещения занимают около 1 ч 45 мин из восьми: печать идёт «по слоям», и
на каждом слое сопло обходит все 28 деталей. Разбивка на плиты этого не
меняет — обходов столько же, просто они разнесены по запускам.

## Печать: 3MF под Bambu Lab A1

`make_3mf.py` собирает готовый проект Bambu Studio. Профиль печати берётся
из скачанной заготовки `Заготовки/ДИМА_7.4.3mf` — там уже лежит рабочая связка
**Bambu Lab A1 0.4 nozzle / 0.20mm Standard @BBL A1 / Bambu PLA Basic @BBL A1**.
Копируется только профиль; метаданные MakerWorld (`DesignModelId`,
`MakerLab*`) в наши файлы не переносятся. Модель ставится в центр стола
256 × 256 мм.

Поверх профиля применяются три правки (`OVERRIDES` в скрипте):

| Ключ | Стало | Зачем |
|---|---|---|
| `enable_support` | `0` | см. ниже — поддержка лезет внутрь канала |
| `ironing_type` | `top` | глажка верхних поверхностей, ради гладкого верха |
| `sparse_infill_density` | `25%` | плотнее опора под верхней коркой |

### Грабли: `different_settings_to_system`

Мало положить значения в `project_settings.config` — Bambu Studio при открытии
проекта разрешает `print_settings_id` в **системный** пресет и берёт значения
оттуда. Что именно в проекте отличается от системного, она узнаёт из отдельного
списка `different_settings_to_system`. Формат — по одной строке на слот:
`[процесс, пруток…, принтер]`, ключи внутри строки через `;`.

В заготовке MakerWorld там лежит `[""]` — пустая строка, да ещё и длиной 1
вместо 3. Из-за этого настройки проекта не доезжают до интерфейса: глажка
показывается как «Без разглаживания», а пруток остаётся тем, что был выбран
в слайсере. Скрипт теперь считает реальное отличие от системного пресета
(разворачивая цепочку `inherits` в `resources/profiles/BBL`) и пишет,
например, `["ironing_type;sparse_infill_density", "", ""]`.

Ключи, которых в пресете процесса нет вообще (`brim_type` живёт в дефолтах
кода), в этот список не попадают — скрипт их отсеивает и пишет примечание.

Проверить после открытия проекта: **Качество → Разглаживание → Тип
разглаживания** должно быть не «Без разглаживания», а имя пресета процесса
показано как изменённое.

Заметьте: `enable_support = 0` в списке отличий не появляется — это и есть
системное значение по умолчанию, так что поддержки выключены в любом случае.
А вот в заготовке MakerWorld стоит `enable_support = 1`, и по той же причине
до интерфейса оно тоже не доезжало.

### Почему без поддержек

Это не «на глаз». В исходной заготовке MakerWorld стоит `enable_support = 1`,
и слайсер при этом печатает поддержку **с Z 0.20 до 8.60 мм** — то есть внутри
канала Ø7.8, который идёт с 1.10 до 8.90. Вынуть её оттуда нельзя, карандаш
просто не влезет.

Других навесов в детали нет: буквы выдавлены вертикально от стола, а свод над
каналом слайсер кладёт мостом (4–8 с на имя). Bambu Studio при выключенных
поддержках показывает предупреждение «has floating regions» — это и есть тот
самый мост, оно ожидаемо.

### Свод над каналом

Над каналом у самых низких букв всего `height/2 − down − hole/2 = 0.85` мм,
это 4 слоя по 0.2. Так устроен и оригинал. Если нужен запас потолще —
увеличьте `--height`: при `--height 12` свод вырастает до 1.85 мм.
Генератор печатает толщину свода в отчёте и ругается, если она меньше 0.8 мм.
